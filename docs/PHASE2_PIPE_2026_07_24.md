# Phase-2 send-ahead pipeline (PIM_STREAM_PIPE) — 2026-07-24

**Target:** the corrected wall map's ~41 ms/request of host build+send
not overlapped with silicon time (request wall 103 ms = 62 ms silicon
+ ~41 ms host). Design: every exec flows through pend_recv +
consume_one; pipe OFF = consume immediately (byte-identical platform
call sequence); pipe ON = receives defer so later rounds' build+send
hides under earlier rounds' silicon. Send order — and the DDR-side
timeline, hence the 2026-05-04 write-then-use locality constraint —
unchanged by construction.

## The unbounded-deferral hang (and its geometry)

First implementation deferred ALL receives to a request-end drain →
DETERMINISTIC hang at the first pipe-ON twin. Captured live (no
ptrace needed — /proc/<pid>/task/*/wchan):
- drain thread: S, wchan=xdma_engine_read_cyclic (c2h starved — the
  FPGA stopped producing);
- main thread: R, wchan=0 (receiveData spinning on the empty
  api_recv_buf at the final drain).
Diagnosis: the build-9 ping-pong was only ever validated with the
host ≤1 program ahead (phase-1's recv pacing guaranteed it);
unbounded h2c send-ahead outruns execution and loses programs
(idle-bank clobber class). NOT a host-buffer limit (API_BUF_SIZE
2 MB > the 670 KB full-deferral footprint). Follow-up filed: box-TB
verification of frontend tready backpressure at >1-ahead; RTL
hardening if absent.

Fix: **PIM_PIPE_DEPTH (default 1)** — bounded send-ahead inside the
validated envelope. Depth 1 already hides the host per-program
build+send (~128 µs) under the ~194 µs silicon time.

## WALL RESULT: −30% measured mid-run; production-gated by a rare stall

Full-model run (stream + pipe depth-1): ran CLEAN for 3,850+ requests
with **total ≈ 71–75 ms, recv ≈ 25–30 ms** per V2 request (baseline
103 / 62 ms) — the projected phase-2 gain, measured. Then STALLED
with the known geometry (drain starved in xdma_engine_read_cyclic,
main spinning in receiveData; watchdog caught it in 300 s with the
wchan evidence in the event).

Read: a ~1/4,000-request LOST-RECORD event under exec-overlap —
depth-1 exec sends overlap COMPUTE-program execution, silicon
territory phase-1 never entered (its exec sends were recv-paced; only
wcol payload-0 sends ever ran ahead; the build-9 ladder overlapped
READ programs only). A lost program = a silently missing record — no
poison (nothing malformed arrives), the pending recv waits forever.
The twin gates (345 pipe-on twins) were an order of magnitude too
short to see it; the correctness result stands (gate ≡ control).

VERDICT: PIM_STREAM_PIPE stays default-OFF. The −30% is real and
waiting behind an RTL reliability fix: box-TB reproduction of the
swap/load-during-compute loss (frontend tready/backpressure at
1-ahead during MAJ3 bodies), fix → build-11 → re-gate → re-wall.
Software side is DONE (implementation, depth cap, twin gates,
watchdog discipline).

## The stall DECODED (07-24 night): deterministic window, environmental arrival

- Position discriminator: the identical-config rerun sailed past the

- **Verilator scenario F (box tb_stream, frontend-inclusive) REPRODUCES
  THE LOSS: 3/3 seeds, ~17% of instruction words missing by program
  ~255** under randomized fin delays (10..1200 cy) + eager producer —
  the depth-1 regime C's fixed 40-cycle fin never entered. The loss is
  a deterministic timing window in the build-9 ping-pong load path;
  production's "1/4k" was merely how often its send cadence entered

- RTL iteration is now seconds-scale. Next: shrink to a minimal

## RC-V2 (consts-into-V2) twin gate: ELEVATED — and correctly read

rcgate (PIM_RESIDENT_CONSTS=1, PIM_RC_ALTERNATE twins): V2 345/345 at
floor but elements +6% (850,503 vs the 802k band); **MM3D 161/720 vs
the 100-104 control band**. Decode: with rc_mode=1 the MM3D bodies
used consts in BOTH twins — the elevation measures the consts path's
OWN rerun jitter: emit_const_clone = RowClone = an ANALOG copy with
per-execution flake on marginal columns, replacing a DIGITAL wrRow.
Consts trade write time for clone jitter — absorbed downstream per
the 07-19 output-level validation (byte-identical text, 33k
requests). The twin gate measures exactly the jitter the lever adds,
so it cannot bless this lever alone; deciding pair = output sanity +
wall delta. Wall run (stream, no pipe, PIM_RC_V2=1) IN FLIGHT vs the
1,847.6 s baseline. Instrument note added to the twin-gate label:
levers that swap digital ops for analog ops raise the twin floor by
construction — judge those at output level.

## RC-V2 wall: −31% ON ITS OWN — then the loss window, WITHOUT the pipe

wall_rcv2 (PIM_STREAM=1, NO pipe, consts on both paths): ran ~3,780
requests at **total 70.8 ms, recv 35.7 ms, exec 15.1 ms** (baseline
103/62/20) — consts-V2 ≈ −31% alone, multiplicative with phase-2 —
then STALLED with the lost-record geometry (main spinning 117 s CPU,
drain starved). PLAIN streaming's wcol bursts are payload-0 sends
with no pacing — they were ALWAYS >1-ahead; consts' shorter bodies
shifted production timing into the loss window for them too. The
07-23 clean walls ran outside the window by timing luck/profile.

RE-RANKED: **build-11 is the critical path** — it now gates phase-2
(−29%) AND consts (−31%), which compound to ≈2× e2e. Interim
software mitigation candidate (pace payload-0 sends by popping their
trailer records — bounds every producer at ≤1-ahead) depends on
drain-side trailer visibility; RTL fix is the real answer.
